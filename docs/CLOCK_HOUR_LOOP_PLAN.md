日期：2026-11-23。本页在打分之前写定。它替换同一文件里先前那一版：那一版用的是中心化 κ=1，再加一个和为 0 的钟点项。那个公式没有成为已发表的方法，本页不再用它。

- [PR #27](https://github.com/JeromeWang6066/SW/pull/27)，分支 `exp/cell-affine-robust`。被检查的方法是「旧公式再加钟点偏差」。
- [PR #28](https://github.com/JeromeWang6066/SW/pull/28)，分支 `exp/cell-affine-seedcheck`。判定只保留周一到周五。

实现以 `scripts/23_cell_affine_next.py` 的 `hour_offsets` 和 `scripts/19_cell_affine_v2.py` 的 `solve_old` 为准。本实验调用它们，不改它们的数值。

## 0. 先读这一节

要回答的问题只有一个：把这套系数从「训练窗上拟合一次」改成「每个同类日开始时，用最近三个同类日重估」，周一到周五的测试 MAE 是否低于已经发表的那一次拟合。

已经发表的结果，本页当作前提，不重新判定：

- 旧公式 λ=72 再加 κ=3 的钟点偏差，六个旧任务的全市测试 MAE 都低于只做 λ=72。见 `cell_affine_next.md`。
- 这组成绩没有通过事先写定的六项稳健性检查。周末六个任务都高于 λ=72；芝加哥种子 43 只有 29 个过门格更低；κ=1 没有在六个任务上都更低。见 `cell_affine_robust.md`。
- 种子 45、46 的工作日测试 MAE 仍低于 λ=72。周末不进入那次判定。见 `cell_affine_seedcheck.md`。

周末退步来自把三个工作日上学到的钟点偏差用到了周六周日。闭环按日型分开重估，是针对这一条，不是再换一个损失。

**信息集。** 闭环在一天开始时，可以使用这一天之前已经发生的实际上车量。验证段和测试段里过完的小时会进入后面几天的拟合。ST-Net 不更新。因此闭环的数字不能和论文里的直接训练放在一张表里。只拟合一次的臂不用 72 小时之后的实际值，必须复现已发表的数字。

**硬约束：**

- 不重训。种子 42 到 46 的微调权重只做前向。
- 不改 λ=72 的含义，不改 κ=3，不搜索窗口长度。
- 不做中心化公式，不去均值，不把钟点偏差改成别的收缩。
- 不重做已经没有超过 λ=72 的 L1 仿射、中位数截距和残差门。
- 不按格子做开关。已经定位到的退步是周六周日这一类，不是散落的格子。
- 150 门不改。50 格的名单用种子 42 训练窗的原始上车合计，五个种子必须相同。其余 157 格保持微调。
- \(p'\) 不送回 ST-Net。一天内部不再更新。
- 测试集在验证集结果写入文件之后才打开。判定只用周一到周五，和 PR #28 相同。

## 1. 公式

对一个窗口里的一个过门格，\(p_t\) 是微调的反归一化预测，\(y_t\) 是实际上车量。\(n\) 是窗口里的小时数。主臂的窗口是 3 天，\(n=72\)。

\[
(a,b)=\mathrm{solve\_old}(p,y,m=1).
\]

`solve_old` 里的惩罚是 \(\lambda=m\cdot n\)。\(m=1\) 时 \(\lambda=n\)，三天窗口上就是已发表的 λ=72。

残差是 \(e_t=y_t-ap_t-b\)。把窗口按钟点折起来，\(n_h\) 是钟点 \(h\) 的个数。三天都完整时 \(n_h=3\)。

\[
s_h=\frac{\sum_{i=1}^{n_h}e_{h,i}}{n_h+3},\qquad p'_t=ap_t+b+s_{t\bmod 24}.
\]

这就是 `hour_offsets(residual, kappa=3)`。三天窗口上 \(s_h\) 等于该钟点残差均值的一半。分母里的 3 是固定的 κ，不随天数去换一个新的 κ。天数变了，收缩比例会变；所以主臂把天数锁在 3，公式和已发表的那一次拟合相同，变的只是窗口落在哪些天。

\(s_h\) 各自向 0 收缩，不要求 24 个钟点的和为 0。已发表的方法就是这样。本实验不加这条约束。

## 2. 每天怎么取窗口

工作日是周一到周五，周末是周六和周日。不用 `is_weekend_or_holiday`：那个函数把劳动节算进周末类，而 PR #27、#28 的工作日就是周一到周五。2016-09-05 是周一，在本实验里是工作日。

对目标日 \(D\)：

1. 向前取严格早于 \(D\) 的最近 3 个同类日，每天 24 小时。
2. 在这 72 小时上按第 1 节拟合 \(a,b,s_h\)。
3. 用到 \(D\) 的 24 小时。这一天的实际值从下一天起才能进入窗口。
4. 同类日少于 3 个时，这一天退回微调。按第 4 节的预热，正式运行不会走到这里。

日期：

| 目标日 | 类别 | 窗口 |
|---|---|---|
| 2016-09-03 | 周六 | 2016-08-28、08-27、08-21 |
| 2016-09-05 | 周一 | 2016-09-02、09-01、08-31 |

09-05 的窗口就是训练窗。这一天的系数必须和只拟合一次的臂一致。第一个会和训练窗不同的工作日是 09-07，它的三个工作日是 09-05、09-02、09-01。

## 3. 实验臂

五个种子都跑：42、43、44、45、46，源城是纽约和芝加哥，共十个任务。

| 代号 | 窗口 | 钟点偏差 | 何时重估 | 角色 |
|---|---|---|---|---|
| B0 | 无 | 无 | 不重估 | 一律微调 |
| O72 | 训练窗，一次 | 无 | 不重估 | 已发表的 λ=72 |
| OL | 训练窗，一次 | κ=3 | 不重估 | 已发表的「旧公式再加钟点偏差」，主对照 |
| RL | 最近 3 个同类日 | 无 | 每天 0 点 | 只滚动直线 |
| CL | 最近 3 个同类日 | κ=3 | 每天 0 点 | **主方法** |
| CL72 | 目标日之前的连续 72 小时 | κ=3 | 每天 0 点 | 对照：窗口不分类别 |

OL 和 CL 的差别只有窗口会不会随日子移动。RL 和 CL 的差别只有有没有 \(s_h\)。CL 和 CL72 的差别只有窗口是否按周一到周五、周六周日分开。

## 4. 数据

种子 42、43、44 的 train、val、test 缓存沿用 `logs/cell_affine_v2_cache/`。本机主目录没有这份缓存时，用 `sw-affine-v2` 工作树里的副本，或先跑脚本 19 的 `--stage predict`。

种子 45、46 的权重要在本机：`finetune_{ny,chi}2dc_seed45.pt`、`_seed46.pt`。对这两个种子补 train、val、test 三段前向，写入 `logs/clock_hour_cache/`。全市测试 MAE 必须和对应的 `logs/G1C-*_seed45.json`、`_seed46.json` 相差不超过 \(10^{-3}\)，这是 PR #28 用过的核对。

另外对十个任务补标签小时 `[5592, 5832)` 的前向，即 2016-08-21 00:00 至 08-30 23:00。同一套前向再跑 `[5832, 5904)`，与已有 train 缓存或本次 train 前向的最大绝对差不得超过 \(10^{-3}\)。通过后，训练窗以原来的 72 小时为准。

闭环从 2016-09-03 连续跑到测试段最后一天。测试段从 2016-11-02 00:00 起，共 60 天。测试段第一天的窗口落在验证段里。

## 6. 必须先通过的核对

任何一条不过就停止。

1. 十个任务的过门名单与种子 42 的 50 格相同。
2. 种子 42、43、44 上，O72 的全市测试 MAE 与 `cell_affine_v2.md` 的「旧公式 λ=72」相差不超过 \(5\times10^{-5}\)。OL 的全市测试 MAE 与 `cell_affine_next.json` 里「旧公式再加钟点偏差」相差不超过 \(10^{-6}\)。
3. 种子 45、46 上，B0 的全市测试 MAE 与训练日志相差不超过 \(10^{-3}\)。
4. 每个臂、每一段，157 格与 B0 的最大绝对差是 0。
5. 改某一个目标日的 \(y\)，这一天的 \(p'\) 不变，下一个同类日的 \(p'\) 可以变。
6. 09-05 上，CL 的 \(a,b,s_h\) 与 OL 的差不超过 \(10^{-8}\)。09-03 上，CL 的窗口是 08-21、08-27、08-28，不含 08-31 至 09-02。
7. 任意一段 72 小时上，本实验的 \(s_h\) 与 `hour_offsets(..., kappa=3)` 的差不超过 \(10^{-8}\)，\(a,b\) 与 `solve_old(..., 1)` 的差不超过 \(10^{-8}\)。

## 7. 指标和判定

判定只用周一到周五的小时。测试段里这样的小时是 1032 个，合 43 天。周六周日照实报告，不作为通过条件。

主指标是这些小时上、207 格的 MAE，口径与 `score_arrays` 相同，只是先去掉周末小时。同时报告这些小时上的 RMSE。MAPE 不参与判定。

区间按这 43 个工作日做块自助，2000 次，生成器种子 0。差是前者减后者。

**主比较**：种子 42，CL 对 OL，两个源城的工作日测试 MAE。

- **CL 更低**：两个源城的差的 97.5% 分位都小于 0，并且 CL 的工作日 RMSE 都不高于 OL。
- **CL 更高**：任一源城的 2.5% 分位大于 0。
- 其余写**无法区分**。

**稳定性**：十个任务的工作日 MAE 差符号全部相同且不为 0，才写「方向稳定」。种子 45、46 在打分前就列入这十个任务，不作为失败之后的补救。

**次要比较**，只报告，不改主结论：

| 比较 | 回答的问题 |
|---|---|
| CL 对 RL | 滚动时，钟点偏差本身还有没有用 |
| CL 对 CL72 | 把周六周日混进窗口，工作日会不会变差 |
| OL 对 O72 | 复现已发表的钟点偏差优势，确认接线没变 |
| 周末切片上的 CL、OL、O72 | 分开重估之后，周末相对 λ=72 是更高还是更低 |

**不允许的说法：**

- 用验证集改 κ、改天数，再把新选择的测试 MAE 当成主结果。
- 把闭环和论文里的直接训练放在一张下降比例表里。
- 因为周末切片变好或变差，改写第 7 节的主结论。
- 用全市 60 天的 MAE 代替工作日 MAE 做判定。PR #28 已经把周末拿出判定。

## 10. 报告里要写的局限

测试段在 PR #27、#28 之前就已经看过。这次仍是探索性对照。

训练窗是三个工作日。OL 把从这三天学到的 \(s_h\) 用到整个测试段，包括周六周日；CL 的周六周日用更早的周六周日重估。两条臂的周末信息集不同，所以周末切片只描述。

κ=3 不是这条闭环新选的。PR #27 的灵敏度里 κ=6、12、24 的点估计也低于 λ=72，但那一页写明不替换 κ=3。本实验也不替换。
