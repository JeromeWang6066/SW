# 1km 格子每天的上车量够不够撑起三天轮廓

通道是出租上车。格子里的数是该小时的上车次数，而且是整数。一个格子一天的数据量是 24 小时相加。
有效格仍是全年上车之和大于 0，所以一个格子可以在工作日几乎没有上车、却仍然有效。
工作日是周一到周五，假日留在工作日里。长窗口是训练段前 5904 小时里的 176 个工作日。短窗口是 2016-08-31 至 2016-09-02，下标 [5832, 5904)。
自身相关是同一个格子的短轮廓和长轮廓的皮尔逊相关。档位仍是不超过 0.5、大于 0.5 且不超过 0.8、大于 0.8。
按上车量加权，是用长窗口的工作日日均上车量做权重，只加在两个窗口都有定义的格子上。
这一步没有训练。脚本复算了已发表的自身相关中位数和三天分档人数，对不上就会停。

## 三天里的一个小时会不会改掉轮廓

单小时上车占比是这三天里最大的那个小时，占这三天总上车的比例。单日占比是三天里最多的那一天。
形状占比是居中之后的平方和里，最大的那个小时占多少。24 个小时若贡献相同，每个小时约是 0.0417。
去掉最大小时，是把该小时换成其余 23 小时的均值，再和长轮廓做相关。差值为正，表示这个小时在把短轮廓拉离长轮廓。
去掉一天的极差，是三次「留两天」得到的相关里，最大减最小。

## 读法

华盛顿有效格 207 个。工作日日均上车量的中位数是 8.02，平均数是 152.4。日均低于 1 的有 30 个，这三天上车中位数是 0。日均 1–9 的有 84 个，占有效格 40.6%，占上车量 1.2%；这三天每个格子上车中位数 12，24 小时里为 0 的个数中位数是 16。日均不低于 200 的有 27 个，占上车量 87.8%，三天上车中位数 1607，为 0 的小时中位数是 0。

这三天轮廓对长轮廓的自身相关，1–9 档中位数 0.4251，不低于 200 档 0.9692。日均上车量和自身相关的 Spearman 是 0.8575。1–9 档里，单个小时占这三天上车量超过 25% 的格子占 35.4%；去掉最大的那个小时后，相关上升超过 0.05 的占 12.5%。不低于 200 档这两项是 0.0% 和 0.0%。

纽约→华盛顿，有定义格子的档位一致比例是 88/189 = 0.4656，按上车量加权是 0.9627。1–9 档是 21/82 = 0.2561，不低于 200 档是 27/27 = 1.0000。芝加哥→华盛顿全部有定义格子是 95/189 = 0.5026，按上车量加权 0.9610。

连续三个工作日共 174 个窗口。这些窗口先在格子上取相关中位数，再在窗口之间取中位数，是 0.6652。协议这三天是 0.6054，174 个窗口里只有 11 个不高于它。这三天比大多数连续三个工作日更散。流量档之间的差距比这个窗口差更大。

日均不低于 50 的格子，纽约方向 48/51 = 0.9412，芝加哥方向 47/51 = 0.9216。日均不低于 10 的格子是 60/93 = 0.6452 和 61/93 = 0.6559。3×3 邻域求和后是 150/207 = 0.7246 和 169/207 = 0.8164。完整 2km 块是 34/56 = 0.6071 和 33/56 = 0.5893。0.7 仍是原来的描述门槛，不是这条脚本新定的规则。
