# 150 门以下的格子按留出日加入闭环

日期：2026-11-24。本页在打分之前写定。

150 门不改，也不换成另一个固定数。过门的 50 格每天都校正。闭环只决定另外 157 格要不要在当天加入同一套校正。

公式仍是 `solve_old(..., 1)` 加 `hour_offsets(..., kappa=3)`，窗口仍是目标日之前最近三个同类日。不重训，不把 \(p'\) 送回 ST-Net。

## 1. 当天怎么放行

对目标日 \(D\)，取严格早于 \(D\) 的最近三个同类日，共 72 小时。工作日只找周一到周五，周末只找周六周日。2016-09-05 仍是工作日。

过了 150 门的格子：在这 72 小时上拟合，用到 \(D\) 的 24 小时。这就是已有的 CL。

没过 150 门的格子先留出日，不直接套用：

1. 三天里每次留出一天。另外 48 小时上用同一套公式拟合。
2. 比较留出那 24 小时的绝对误差合计。校正比微调至少低 \(10^{-6}\) 辆，这一天算赢。相等不算赢。
3. 赢的天数达到票数，这一格在 \(D\) 才校正。用到 \(D\) 上的系数是完整 72 小时的拟合，不是留出日那次拟合。
4. 票数不够的格子当天保持微调，和微调逐位相同。

\(D\) 的实际值不进入这一天的留出日，也不进入这一天的系数。

## 2. 票数

三档都算：1 票、2 票、3 票。

**主比较是 2 票。** 1 票和 3 票只报告，不另选，也不改主比较。验证集不用来改票数。

## 3. 对照和判定

对照是 CL：只有 50 格校正。差是「2 票减 CL」。

种子 42 到 46，纽约和芝加哥，共十个任务。主比较只用种子 42 的两个源城。指标是周一到周五、207 格的 MAE，口径与 `score_arrays` 相同。同时看这些小时的 RMSE。

区间是工作日的块自助，2000 次，生成器种子 0。测试段应有 1032 个工作日小时。

- **更好**：两个源城的 97.5% 分位都小于 0，并且 2 票的工作日 RMSE 都不高于 CL。
- **更差**：任一源城的 2.5% 分位大于 0。
- 其余写**无法区分**。

十个任务的工作日 MAE 差符号相同且不为 0，才写「方向稳定」。

另外写明：工作日上平均每天新加入多少格，以及这些新加入的格子自己的绝对误差合计是下降还是上升。全市 MAE 几乎不动、只是多了一批格子，不能写成更好。

周末照实写，不参与主比较。

## 4. 必须先通过的核对

1. 只有 50 格校正时，种子 42 的验证集、以及十个任务的测试集，工作日 MAE 与 `clock_hour_loop` 里的 CL 相差不超过 \(10^{-8}\)。
2. 过门的 50 格与 CL 逐位相同。2 票没有改动它们的系数。
3. 没被放行的格子与微调逐位相同。
4. 改目标日的 \(y\) 不改变这一天的胜场。这一条由单元测试覆盖。

任何一条不过就停止。

## 6. 种子 47 和 48

这一节在这两个种子打分之前写定。主比较仍是第 3 节的种子 42、2 票，不因为新种子改票数或改 150 门。

两个种子用 `configs/finetune_ny2dc.yaml` 和 `configs/finetune_chi2dc.yaml`，只把 `--seed` 换成 47 和 48。权重名为 `finetune_{ny,chi}2dc_seed47.pt`、`_seed48.pt`。前向写入 `logs/clock_hour_cache/`，包含 `[5592, 5832)` 以及 train、val、test。

核对：四个新任务的微调全市测试 MAE 与对应 `logs/G1C-*_seed47.json`、`_seed48.json` 相差不超过 \(10^{-3}\)。过门名单仍是种子 42 的 50 格。

通过：四个新任务里，2 票的工作日 MAE 都低于该任务只校正 50 格的 CL。有一个不低于，这次核对就不通过。原来十个任务的结论不改写。十四个任务的差符号全部相同，才把稳定性写成十四个任务。
