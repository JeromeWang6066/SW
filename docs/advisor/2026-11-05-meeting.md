# 导师会议记录（2026-11-05）

> 会后整理，不是逐字稿。0.8 和 0.5 是导师举的例子，不是已经定下来的阈值。本节不新增实验结果。已有数字以 [RESULTS.md](../RESULTS.md) 为准。

## 背景

会议时，华盛顿 3 天协议上已经有三种子结果：源城权重复制后微调，测试 MAE / RMSE 低于随机初始化蒸馏，也低于先复制权重再蒸馏。芝加哥微调的三种子均值最低（测试 MAE 1.5171，RMSE 5.0568）。纽约随机初始化蒸馏在种子 43、44 上差于从零训练。导师针对这个现象提了下面三条。

## 建议 1 — 微调已经更好时，为什么还要蒸馏

导师的问题：如果 fine-tuning 的效果好于蒸馏，为什么不直接微调？

整理后的含义：

- 蒸馏不是默认方法。当前两对迁移（纽约→华盛顿、芝加哥→华盛顿）里，纯微调在 MAE / RMSE 上更稳。
- 蒸馏要保留的理由，是源城和目标城只部分相似：直接复制权重会把不相似的空间模式也带过去；蒸馏只用教师输出做软目标，学生仍在目标城数据上学习。
- 因此下一步不是再证明“蒸馏全面优于微调”，而是回答：在什么相似度下微调更好，在什么相似度下蒸馏更好。

和现有表的关系：纽约随机蒸馏的三种子平均测试 MAE 是 1.9422，高于华盛顿从零训练的 1.8850。这是负迁移，正好说明不能凡是跨城就蒸馏。芝加哥教师初始化、λ = 0.1、种子 42 的测试 MAE 1.4783 接近纯微调，但只有一个种子，不能单独当成“蒸馏可以超过微调”的结论。

## 建议 2 — 用 Pearson 相关决定用微调还是蒸馏

导师的做法：

1. 做多次不同的迁移实验，每次算出一个皮尔森相关。
2. 相关高过某个上阈值时，直接微调。
3. 相关低一些、但仍然有可学习、可借鉴的结构时，用蒸馏。
4. 导师举例：大于 0.8 微调；大于 0.5 且小于 0.8 蒸馏。
5. 这两个数要靠多次实验、多个种子跑完后再定，不能先写死。

计划里据此写成三档，第三档是会上没有逐字规定、需要下次确认的补全：

| 相关 ρ | 方法 | 状态 |
|---|---|---|
| ρ > τ_high | 源城权重复制到目标城，只做任务损失微调 | 导师明确说了。τ_high 的例子是 0.8 |
| τ_low < ρ ≤ τ_high | 蒸馏 | 导师明确说了。例子是 0.5 到 0.8 |
| ρ ≤ τ_low | 不用源城，只在目标城少样本上训练 | 会上没定。默认先这样写，下次确认 |

定阈值时分开两件事：

- **多种子**看的是“谁赢”稳不稳。同一份数据、同一种轮廓，换种子不会得到一个新的 ρ。种子 42/43/44 不能当成三个不同的相关样本。
- **多个实验**才会得到一列不同的 ρ。现在只有纽约→华盛顿、芝加哥→华盛顿两条，定不出 0.8 和 0.5。三座城可以做六个有向对：纽约↔芝加哥、纽约↔华盛顿、芝加哥↔华盛顿。目标侧仍用现有的 3 天协议。出租和单车、不同功能区，是在这六个方向之后再加的相关样本，不先混进同一个数。

阈值只在验证集上选。测试集每个设定只评估一次，用来报告选定规则，不用来来回调阈值。

比较时每个城市对、每个种子都跑齐三条：目标城从零、源城权重微调、冻结教师的标准蒸馏。教师初始化再蒸馏、以及 λ，留到分流规则在验证集上看出分界之后再加，避免一次矩阵过大。

## 建议 3 — 给格子增加功能标定，而不只是车流量

导师的问题：网格是按真实路网切出来的。除了格子之间的车流量、上车和下车数量，能不能事先给格子做一个功能划分（predetermination），再看两个城市的功能区会不会影响迁移。

现有数据包里已经有这些静态或可事先算出的量，不需要新爬数据：

| 标定 | 来源 | 用途 |
|---|---|---|
| 兴趣点构成 | `{CITY}_poi.npy`，形状 `(H, W, 14)` | 14 类占比。城市间密度不同，用占比，不用原始计数。类名落地时对照上游 `data_readme`，不在文档里猜 |
| 路网连接 | `{CITY}_roads.npy`，形状 `(H, W, H, W)` | 每个格子连到多少别的格子。这是“切块对应真实路网”的直接用法 |
| 上下车比 | `Taxi{CITY}_pickup.npy` 与 `dropoff.npy` | 早高峰上车多、下车多，对应居住和就业的粗差别。目标城只用 3 天训练窗估计 |
| 日轮廓形状 | 工作日 24 小时均值，代码里已有轮廓函数 | 峰在几点、是不是早晚双峰。这就是现在的 Pearson 轮廓，同时当作功能特征 |
| 周末相对工作日 | 同一套小时网格，按星期掩码分开 | 周末更高的格子更像休闲区。掩码只用训练段 |
| 出租与单车的比例 | 包内 Bike 与 Taxi 都有 | 方式构成。单车有效格和出租有效格不同，先只在两者都有效的格子上算 |

功能标签先做分析，不改 ST-Net：

1. 兴趣点占比上做聚类，得到少数几类功能区。路网度、上下车比用来检查聚类是否说得通，不先并成一个黑箱分数。
2. 报告误差时按功能区分层，看迁移收益落在哪一类格子上。
3. 跨城不对齐整张网格（纽约 20×23、芝加哥 17×28、华盛顿 21×20，有效格 458 / 270 / 207）。相关和蒸馏范围限制在功能类一致的格子之间。
4. CrossTReS 的 `functional_forward` 和 region re-weighting 仍不移植。这里的“功能”是迁移前的格子标签，不是再训一个功能网络。

兴趣点、路网是静态的，可以用全时段。凡是从流量算出来的标签（上下车比、峰时、周末差），源城用训练段，目标城只用 3 天训练窗，不用验证集和测试集。

## 建议落地的顺序

1. **只统计、不训练。** 三城算出兴趣点占比、路网度、上下车比、工作日 24 小时轮廓。每个有向城市对先记一个粗 Pearson：两边有效格平均轮廓的相关，并写明这不是最终的格子匹配。
2. **六个有向城市对 × 从零 / 微调 / 蒸馏 × 三个种子。** 验证集上画 ρ 对“微调 MAE − 蒸馏 MAE”。看分界是否靠近导师举的 0.8 和 0.5；对不上就改阈值，不改实验事实。
3. **功能区分层。** 用兴趣点聚类给格子贴标签，按类报告测试误差。再决定蒸馏或微调是否只作用在功能一致的格子上。
4. **原 Group 3 的 ρ̃ 乘子后做。** 只有验证集显示，中等相关区间里蒸馏稳定好于微调和从零训练，才把相关写进蒸馏损失。相关已经高到微调更好时，乘子没有必要再去压过微调。

## 下次见面需要确认的四点

1. ρ 不超过下阈值时，是否退回“只训目标城”。
2. 一个实验只记一个城市级 ρ，还是每个格子记一个 ρ、格子级分流。
3. 第一批功能特征是否就是兴趣点占比、路网度、上下车比。
4. 是否同意把华盛顿也当作源城，做满六个方向。不做的话，相关样本只有两条，定不出阈值。
